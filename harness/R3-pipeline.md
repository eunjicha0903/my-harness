# R3. 파이프라인

## 단계 분할 (★ = 프로젝트 첫 실행에서만)

| 단계 | story-work.md 문장 | 입력 | 출력 |
|---|---|---|---|
| S1 레퍼런스 | 1, 2 | 화면 이름, story-service.md | 레퍼런스 목록, 분석 및 반영 항목 |
| S2 화면 설계 | 3 | S1 출력, story-service.md | 화면 설계 문서 |
| S3 컨셉 ★ | 4, 5, 6 앞부분 | S2 출력, design.md | 키스크린 2~3개, 토큰, 컴포넌트 (Figma) |
| S4 화면 디자인 | 6 뒷부분 | S2 출력, 토큰, 컴포넌트 | 화면 프레임 (Figma) |
| S5 검토 | 7 | S4 출력, design.md, story-service.md | 판정 결과 |

- S1의 레퍼런스 수집은 uibowl MCP로 자동 수행한다.
- 두 번째 실행부터는 S3을 건너뛰고 확정된 토큰·컴포넌트를 쓴다.

## 레퍼런스 수량 기준 (S1)

- 화면 1개당 레퍼런스 5개 이상
- 서로 다른 서비스 3개 이상
- 미달 시 S1 재실행

## 결과물 수준 (S3, S4)

- design.md 토큰(색·글자 크기·모서리·폰트)을 적용한 화면
- 이미지는 회색 박스로 대체

## 되돌아가는 지점

| 실패 | 복귀 |
|---|---|
| S1 반영 항목이 화면 목적·니즈와 안 맞음 (작업 흐름 2번의 멈칫) | S1 |
| S5에서 design.md 위반 (색·글자 크기·모서리) | S4 |
| S5에서 story-service.md 위반 (예: 최소 주문 금액 미달인데 주문 버튼 활성) | S2 |
| 같은 단계에서 3회 연속 실패 | 중단 후 본인에게 질문 |
