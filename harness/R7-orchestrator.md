# R7. 오케스트레이터

오케스트레이터 = 프로젝트 루트의 `CLAUDE.md`를 따르는 메인 Claude 세션.

## 책임

오케스트레이터는 산출물을 직접 만들지 않는다. 하는 일은 아래뿐이다.

1. 실행하는 말을 알아듣는다 (R6).
2. 단계별 에이전트를 순서대로 부른다.
3. 게이트(`harness/scripts/judge.js`)를 실행한다.
4. `state.json`을 갱신한다.
5. 사람 승인을 요청한다 (R5).

## 편집 범위 지키기

- `.claude/agents/`에 에이전트 5개(researcher, planner, concept-designer, screen-designer, judge)를 정의하고, 각 정의에 편집 폴더를 적는다.
- judge에는 쓰기 도구를 주지 않는다 (읽기 + 스크립트 실행만).
- 단계가 끝날 때마다 오케스트레이터가 해당 에이전트 편집 폴더 밖에서 바뀐 파일이 있는지 확인한다. 있으면 그 단계는 실패로 처리한다.
- hook으로 막는 방식은 이후 필요하면 추가한다.

## 단계 산출물 양식

G1·G2를 스크립트가 셀 수 있도록 `harness/templates/`의 양식대로만 작성한다. judge.js는 G1·G2·G5를 모두 판정한다.

| 양식 | 필수 구성 |
|---|---|
| `templates/references.md` | 레퍼런스 표 (ID, 서비스명, URL) / 반영 항목 표 (항목, 유저스토리 번호, 레퍼런스 ID) |
| `templates/spec.md` | 연결 유저스토리 번호 / 상태 목록 표 / 화면 구성 |

## 프로젝트 시작 조건

1. "새 프로젝트 `<이름>`" → `harness/templates/project/`의 뼈대 문서 4개를 `projects/<이름>/docs/`에 복사한다. 내용은 본인이 입력한다.
2. 문서를 채운 뒤 "rules 만들어줘" → 오케스트레이터가 design.md·story-service.md에서 `rules.json` 초안을 뽑아 보여주고, 승인 후 저장한다.
3. "`<프로젝트>` `<화면>` 시작해"는 아래 중 하나라도 해당하면 거부하고 빠진 것을 알려준다.
   - `rules.json`이 없음
   - 문서 4개 중 `<서비스명>` 같은 뼈대 자리표시자가 남아 있거나 뼈대와 내용이 같은 파일이 있음
   - 지정한 화면이 `rules.json`의 `screens`에 없음
