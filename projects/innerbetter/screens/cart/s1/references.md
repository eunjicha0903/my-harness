## 분석

이 화면의 목적은 유저스토리 2(상품을 담고 수량을 바꾸면서 최소 주문 금액 충족 여부와 최종 결제 금액을 확인)이고, 지켜야 할 규칙은 "어기면 안 되는 것 #1"(최소 주문 금액 미달 시 부족 금액을 알려주고 주문 진행을 막음)이다. 레퍼런스는 이 두 축으로 봤다.

- **R1 배달의민족(비마트)** — 하단 고정 영역에 남은 금액("13,200원 더 담으면")과 진행 막대를 CTA 바로 위에 둬서 사용자가 스크롤 위치와 상관없이 얼마나 더 담아야 하는지 본다. 조건이 안 채워졌을 때 CTA 문구가 "배달 도착 시간을 선택해주세요"처럼 다음 할 일로 바뀌어 왜 진행이 안 되는지 버튼에서 바로 읽힌다. 상품마다 휴지통/−, 수량, + 스테퍼가 있어 수량을 바꾸면 남은 금액이 바로 달라지는 구조다. 우리 화면의 "부족 금액 안내 + 주문 막기"와 가장 가깝다.
- **R2 해피문데이** — R1과 같은 "N원 더 담으면" + 진행 막대 패턴을 단일 상품 장바구니에 적용. 막대가 CTA와 붙어 있어 금액 → 버튼 순서로 시선이 흐른다. 상품 카드 안에 "최종 금액"을 따로 둬 수량 변경 결과를 카드 단위로 확인한다.
- **R3 포스티** — "결제 금액" 섹션에서 총 상품 금액·배송비·예상 할인 금액을 줄 단위로 나열하고, 최종 금액을 CTA 라벨("17,700원 주문하기")에 넣어 결제 금액을 버튼에서 한 번 더 확인시킨다. 스토리 2의 "최종 결제 금액 확인"에 직접 대응한다. 상단의 "N원 더 담으면 추가 할인" 띠도 부족 금액 안내 문구의 다른 위치 예시다.
- **R4 CJ더마켓** — 배송 그룹 단위 카드 하단에 선택상품금액·할인·배송비·주문금액을 정리하고, 하단 고정 바에 총액과 "주문하기(2건)"를 둔다. 금액 요약을 카드 단위와 화면 하단 두 곳에서 보여 주는 방식. 수량 스테퍼(−, 1, +)가 상품 정보 바로 아래에 있다.
- **R5 네이버플러스 스토어** — 옵션 박스 안에 스테퍼와 해당 옵션 금액(19,900원)을 한 줄로 배치해 수량 변경과 금액 변화가 한눈에 보인다. 하단 고정 "총 주문 예상 금액"과 주문하기 버튼 구성은 R4와 유사.
- **R6 빽다방** — 장바구니 이전 단계(매장 정보)에서 "최소주문금액 12,000원"을 표로 미리 알려준다. 기준 금액 자체를 노출해 사용자가 부족 금액 안내를 이해할 근거를 준다.
- **R7 차란** — 담은 상품이 없을 때 하단 CTA를 "0원 주문하기"로 두되 회색 비활성으로 고정한다. 주문할 수 없는 상태를 버튼 색·상태로 명확히 표현하는 예시. 빈 화면에서 "상품 보러가기"로 되돌아가는 동선도 있다.

공통 패턴: (1) 부족 금액은 "N원 더 담으면" 형태로 CTA 바로 위 하단 고정 영역에 둔다, (2) 진행 막대로 기준 대비 현재 위치를 보여준다, (3) 최종 금액은 금액 내역 + CTA 라벨 두 곳에서 확인시킨다, (4) 수량 스테퍼는 상품 카드 안에서 금액과 함께 둔다.

제외한 것: R1·R2·R3의 무료배송/추가 할인 안내는 "혜택"용이라 그대로 가져오지 않고 "최소 주문 금액(주문 불가 조건)" 용도로만 바꿔 쓴다. R3·R4·R5의 "선물하기" 등 별도 주문 경로는 최소 주문 금액 미달 시 우회 경로가 될 수 있어 넣지 않는다(어기면 안 되는 것 #1). 적립금 자동 적용은 스토리 3(주문 화면) 범위라 이 화면에서 다루지 않는다.
