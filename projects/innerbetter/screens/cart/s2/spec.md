## 연결 유저스토리

| 번호 | 유저스토리 |
|---|---|
| 2 | 저칼로리 식단을 관리하는 사용자가 상품을 장바구니에 담고, 수량을 바꾸면서 최소 주문 금액을 채웠는지와 최종 결제 금액을 확인한다. (PRD 3-2, 6-3) |

## 상태 목록

상태 ID는 Figma 프레임 이름 `<화면>/<상태 ID>`에 그대로 쓴다. rules.json `screens.<화면>.requiredStates`가 있으면 모두 포함.

| 상태 ID | 설명 |
|---|---|
| min-unmet | 담은 상품 금액이 최소 주문 금액에 못 미친 상태. 하단 고정 영역에 부족 금액 문구(txt-shortfall)와 진행 막대를 보여주고, 주문 버튼(btn-order)은 disabled. (story-service.md 어기면 안 되는 것 #1, PRD 6-3 최소 주문 금액 예외) |
| min-met | 담은 상품 금액이 최소 주문 금액 이상인 상태. 진행 막대가 가득 차고 "주문 가능" 안내로 바뀌며, txt-shortfall은 없고, btn-order는 enabled이며 라벨에 최종 결제 금액을 포함. |

## 화면 구성

위→아래 순서. 레이어 이름은 rules.json `naming.layers` 및 `design.marginExemptLayers`를 따른다. 금액 값은 문서에 확정값이 없으므로 `{ }` 자리표시자로 적는다 (S4에서 예시값을 넣을 때도 최소 주문 금액 기준값은 [확인 필요] 항목임을 유지).

1. **status-bar** — 시스템 상태 표시줄 (좌우 여백 예외 레이어).
2. **top-bar** — 뒤로가기 아이콘 + 화면 제목 "장바구니" (좌우 여백 예외 레이어).
3. **상품 목록 영역** (스크롤, 좌우 여백 20) — PRD 6-3 상품 목록·수량 변경·상품 삭제·상품 금액
   - 상품 카드 (담은 상품 수만큼 반복)
     - 상품 이미지, 상품명
     - 상품 삭제 버튼 (PRD 6-3 "상품 삭제")
     - 한 줄 배치: 수량 스테퍼(−, 수량, +) + 해당 상품 금액(단가 × 수량)
     - 수량을 바꾸면 상품 금액, 금액 요약, 부족 금액(txt-shortfall), 진행 막대, btn-order 상태가 함께 갱신된다.
4. **금액 요약 섹션** (좌우 여백 20) — PRD 6-3 상품 금액·최소 주문 금액·할인 금액·최종 결제 금액
   - 줄 단위 나열:
     - 총 상품 금액: `{총 상품 금액}`원
     - 할인 금액: −`{할인 금액}`원 [확인 필요: 장바구니 단계 할인의 종류·적용 규칙]
     - 배송비: `{배송비}`원 [확인 필요: 배송비 존재 여부·금액이 문서에 없음]
     - 구분선
     - 최종 결제 금액: `{최종 결제 금액}`원 (강조)
   - 최소 주문 금액 기준 표시: "최소 주문 금액 `{최소 주문 금액}`원" [확인 필요: 값 미정 — story-service.md 미정 항목]
   - 적립금은 이 화면에서 다루지 않는다 (story-service.md 유저스토리 3 / PRD 6-4 주문·결제 범위).
5. **bottom-area** (하단 고정, 좌우 여백 예외 레이어) — 상태별로 아래와 같이 구성
   - **min-unmet**
     - 부족 금액 문구 **txt-shortfall**: "`{부족 금액}`원 더 담아야 주문할 수 있어요" — 1개 이상 반드시 노출
       - 부족 금액 = 최소 주문 금액 − 현재 주문 금액 [확인 필요: 비교 기준이 할인 전 상품 금액인지 할인 후 금액인지]
     - 진행 막대: 최소 주문 금액 대비 현재 주문 금액 비율만큼 채움, 기준값 "`{최소 주문 금액}`원" 함께 표기
     - 총액 표시: `{최종 결제 금액}`원
     - **btn-order** = **disabled**, 라벨 "주문하기" (탭해도 주문으로 진행되지 않음)
   - **min-met**
     - txt-shortfall 없음
     - 진행 막대 가득 참 + 안내 문구 "최소 주문 금액을 채웠어요" ("주문 가능" 상태 표시)
     - 총액 표시: `{최종 결제 금액}`원
     - **btn-order** = **enabled**, 라벨 "`{최종 결제 금액}`원 주문하기" → 탭 시 주문·결제 화면(order)으로 이동
   - 공통: 주문 버튼 외 다른 주문 경로(선물하기 등)는 두지 않는다 (어기면 안 되는 것 #1 우회 방지, s1 분석 "제외한 것").

## 반영 항목 적용

| # | 반영 위치 |
|---|---|
| 1 | 화면 구성 5. bottom-area / min-unmet — btn-order 바로 위에 txt-shortfall "`{부족 금액}`원 더 담아야 주문할 수 있어요" |
| 2 | 화면 구성 5. bottom-area — min-unmet에서는 부분 진행 막대, min-met에서는 가득 찬 막대 + "최소 주문 금액을 채웠어요" 안내 |
| 3 | 상태 목록 및 화면 구성 5 — min-unmet에서 btn-order = disabled, min-met에서만 btn-order = enabled |
| 4 | 화면 구성 4. 금액 요약 섹션의 "최소 주문 금액 `{최소 주문 금액}`원" 줄 + 화면 구성 5 진행 막대의 기준값 표기 (값 자체는 [확인 필요]) |
| 5 | 화면 구성 3. 상품 카드 — 수량 스테퍼(−, 수량, +)와 상품 금액 한 줄 배치, 변경 시 금액 요약·txt-shortfall·진행 막대·btn-order 동시 갱신 |
| 6 | 화면 구성 4. 금액 요약 섹션 — 총 상품 금액·할인 금액·배송비·최종 결제 금액 줄 단위 (할인·배송비 항목은 [확인 필요]) |
| 7 | 화면 구성 5. bottom-area / min-met — btn-order 라벨 "`{최종 결제 금액}`원 주문하기", 두 상태 모두 하단 고정 바에 총액 표시 |

### [확인 필요] 목록

1. 최소 주문 금액의 구체적인 값 — story-service.md "미정 항목"에 명시. 반영 항목 #4, txt-shortfall 계산에 필요.
2. 최소 주문 금액 비교 기준 — 할인 전 총 상품 금액인지, 할인 후 금액인지 문서에 없음.
3. 배송비 — 반영 항목 #6에 포함됐지만 PRD 6-3 장바구니 필수 기능과 story-service.md에 배송비 존재 여부·금액이 없음.
4. 장바구니 단계 할인 금액 — PRD 6-3에 "할인 금액"은 있으나 할인의 종류·적용 규칙이 문서에 없음 (적립금은 주문 화면 범위).
5. 빈 장바구니(담은 상품 0개) 상태 — 문서에 정의 없음. 상태 목록에 넣지 않았고, 별도 상태가 필요하면 추가 결정 필요.
6. 수량 범위 — 최소 수량(1에서 − 를 누를 때 삭제 처리 여부)과 최대 수량이 문서에 없음.
